  • Restores into a new, isolated ADO project (recommended: a dedicated DR-Test project).
  • Refuses to run if the target repo already exists in ADO.
  • Does not touch original ADO source repos.
  • Restored repos are named with the suffix you specify (e.g. selfhost_dr_restore).
  • After reviewing, manually delete the restored repos from ADO.
How the Restore Drill Works

The dr-restore-drill.yml workflow clones the GitHub mirror copies of your selected repos and pushes them into a fresh ADO project. It then verifies commit parity between the GitHub mirror and the restored ADO repo, and reports the results in the workflow run summary.

  1. Workflow reads your selected repos from GitHub mirrors
  2. Creates new repos in the target ADO project
  3. Pushes all branches and tags
  4. Verifies commit count parity
  5. Reports per-repo pass/fail in the run summary
Tips for a successful drill • Use a separate ADO project (e.g. Test1-DR) as target
• Run quarterly or after any major repo restructuring
• Check the GitHub Actions run summary for parity results
• Delete restored repos from ADO when done
